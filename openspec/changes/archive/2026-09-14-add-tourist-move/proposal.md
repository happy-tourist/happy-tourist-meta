## Why

На поле уже стоят фигурки туристов, но партия ещё не «играется»: нельзя выбрать туриста, увидеть доступные клетки и сделать ход по очереди. Нужна первая механика перемещения — иначе доска остаётся витриной.

## What Changes

- Seated-игроки ходят **по очереди** (порядок входа в room); после успешного хода ход сразу у следующего; один игрок в комнате может ходить сам с собой.
- На своём ходу игрок выбирает **свою** фигурку на поле или в полосе под доской; тайл выбранного туриста обводится белой рамкой; клетки, куда можно шагнуть — красной; подсветку видит **только ходящий**.
- Ход — ровно на **одну** соседнюю клетку (включая диагональ) на проходимый тайл (поле, старт, центр), если клетка не занята любым туристом (в том числе своим).
- После подтверждённого хода фигурка **плавно** переезжает на целевой тайл у всех клиентов; пока анимация идёт, клики ходящего игнорируются.
- Сервер авторитетно принимает/отклоняет ход и синхронизирует позиции и чей сейчас ход; зрители только наблюдают.

## Scope

- **Capability ID:** `game/move` (новая); `game/board` (правка — доска интерактивна для выбора/подсказок/хода).
- **Пакеты:** server (очередь хода, валидация, message хода, sync позиций/хода); client (выбор, подсветка, отправка хода, анимация); meta skills под контракт.
- **Контракт:** room `tourist`; synced «чей ход» + позиции pieces; client→server message хода (идентификатор фигурки + целевая клетка).
- **Экран:** Game (seated vs spectator).

## Out of scope

- Событие «начала партии» / кнопка «готов» (ходы доступны сразу при наличии seated).
- Семантика «финала» на центральных клетках (центр проходим как обычный тайл; особые правила later).
- Пас / пропуск хода; авто-скип при offline (ход **ждёт** reconnect grace).
- Задания на тайлах, статусы strip, смена правил соседства.
- Новые HTTP API / auth / смена рассадки `game/pieces` сверх последствий leave на очередь хода.

## Capabilities

### New Capabilities

- `game/move`: очередь хода, выбор своей фигурки, легальные шаги, авторитетный move, локальные подсказки только ходящему, плавная анимация переезда у всех клиентов.

### Modified Capabilities

- `game/board`: снять запрет на selection / move hints / move submission; доска участвует в UX хода при активной сессии.

## Impact

- Server: room `tourist` — sync текущего хода, обработка message хода, валидация соседства/занятости/проходимости, продвижение очереди; mocha на SC-MOVE-*.
- Client: экран Game — выбор фигурки (поле + полоса), белая/красная подсветка только на своём ходу, send хода через game store, анимация sync-перемещения; зритель без интерактива хода.
- Meta: skills board / game / messages / schema под ход и подсветку.
- Зависимости: без новых npm-пакетов (анимация CSS/клиентский UX).
