## Why

На поле «Счастливый турист» игрок должен сразу видеть **свои четыре одинаковые** фигурки — по одной на каждой стороне доски — и под полем полосу из четырёх слотов, связанных 1:1 с полевыми (для будущих статусов). Текущая реализация (одна фигурка / одна сторона / strip×1) этому не соответствует.

## What Changes

- **BREAKING** (относительно первой версии этого change): у seated-игрока не одна, а **четыре** sync-фигурки одного `touristId` на сторонах N/E/S/W; клетка на стороне — random из **свободных** стартов стороны.
- Вид туриста (`touristId` 1…4) по-прежнему **уникален среди игроков**; у одного игрока все четыре фигурки выглядят одинаково.
- Strip под доской — **только свои** четыре слота (порядок сторон), без туристов соперников; UI статусов later.
- Старт комнаты пока по 4-му seated; кнопка «готов» — out of scope.
- Гости видят фигурки на доске, strip не видят; leave снимает все четыре токена игрока.

## Scope

- **Capability ID:** `game/pieces` (правка); `game/board` (правка — доска показывает все sync pieces).
- **Пакеты:** server (schema + assign 4 tokens/player); client (оверлей ×4 + strip ×4); meta skills.
- **Контракт:** synced seats с `touristId` + pieces по сторонам; game messages по-прежнему нет.

## Out of scope

- Ходы, валидация, очередь ходов, задания на тайлах.
- UI статусов на strip/поле («в игре» / «прошёл») — только задел 1:1 слотов.
- Кнопка «готов» вместо старта по 4-му игроку.
- Визуальное различение владельцев кроме разного `touristId` PNG.
- Forfeit / reconnect policy сверх remove-on-leave.
- Выбор клеток, клики по фигуркам.
- Новые HTTP API / auth / генерация PNG.
